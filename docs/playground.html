02

Why the import fails

Nothing is wrong with the code or with pip. The block happens deeper, at the moment Windows is asked to load a compiled file into memory.

What Smart App Control isA Windows 11 security layer that blocks apps and drivers it cannot verify as trusted. Once it is on and enforcing it can only be turned off, never back on, without a full Windows reset. So "just disable it" is a one-way door you probably do not want for a side project.
03

The fix: signed binaries from conda-forge

The right-hand branch of the diagram is the answer. conda-forge ships the same scientific libraries with code-signed binaries, and Smart App Control accepts them. The security setting does not change; you are just installing files that pass its check.

  1. 1

    Install Miniforge (a minimal conda defaulting to conda-forge). Its installer is itself signed, by NumFOCUS, so it runs fine.

  2. 2

    Create a project environment with python=3.12 and the whole stack. Every binary in it is signed.

  3. 3

    Register it as a Jupyter kernel and pick it in your editor. An existing venv can stay; it still runs everything except the sklearn pieces.

# 1 - install Miniforge (per-user, no admin, does not touch PATH)
#     download: github.com/conda-forge/miniforge/releases/latest
.\Miniforge3.exe /S /InstallationType=JustMe /RegisterPython=0 /D=%USERPROFILE%\miniforge3

# 2 - create the signed environment (a path without spaces avoids a warning)
& $env:USERPROFILE\miniforge3\Scripts\conda.exe create -y -p $env:USERPROFILE\pl-predictor-env `
    python=3.12 numpy pandas scikit-learn xgboost matplotlib jupyter pyarrow joblib

# 3 - verify the exact import that was failing
& $env:USERPROFILE\pl-predictor-env\python.exe -c "import sklearn, scipy; print(sklearn.__version__)"

# register the kernel, then choose "PL Predictor (conda)" in your editor
& $env:USERPROFILE\pl-predictor-env\python.exe -m ipykernel install --user `
    --name pl-predictor --display-name "PL Predictor (conda)"
Why this is the clean answerSmart App Control stays on. No registry edits, no Unblock-File (which would not help; this is not a mark-of-the-web block), no reset. You work with the security model instead of switching it off.

If you would rather not install conda

The whole real pipeline already runs on numpy, pandas and XGBoost, none of which trip the block. The notebooks are written that way on purpose, with the metrics, the Dixon–Coles matrix and the calibration hand-rolled in numpy. You only need scikit-learn if you specifically want its RandomForestClassifier, and the teaching notebook shows a hand-built forest; XGBoost's subsample and colsample_bytree are the same two ideas.
