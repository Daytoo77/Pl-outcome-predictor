Environment fix & interactive playground

The blocked import, and a playground

Windows Smart App Control silently stops import sklearn on this machine. Here's why, a fix that keeps the security feature switched on, and a live playground for the toy ML concepts — running right in the page.

1

Why the import fails

Nothing is wrong with the code or with pip. The block happens deeper — at the moment Windows is asked to load a compiled file into memory.

What Smart App Control is

A Windows 11 security layer that blocks apps and drivers it can't verify as trusted. Once it is on and enforcing it can only be turned off, never back on, without a full Windows reset. So “just disable it” is a one-way door you probably don't want for a side project.

2

The fix: signed binaries from conda-forge

The right-hand branch of the diagram is the answer. conda-forge ships the same scientific libraries with code-signed binaries, and Smart App Control accepts them. The security setting doesn't change — you are just installing files that pass its check.

  1. 1

    Install Miniforge (a minimal conda defaulting to conda-forge). Its installer is itself signed — by NumFOCUS — so it runs fine.

  2. 2

    Create a project environment with python=3.12 and the whole stack. Every binary in it is signed.

  3. 3

    Register it as a Jupyter kernel and pick it in VS Code. The existing venv can stay — it still runs everything except the sklearn pieces.

# 1 - install Miniforge (per-user, no admin, does not touch PATH)
#     download: github.com/conda-forge/miniforge/releases/latest
.\Miniforge3.exe /S /InstallationType=JustMe /RegisterPython=0 /D=%USERPROFILE%\miniforge3

# 2 - create the signed environment  (a path without spaces avoids a warning)
& $env:USERPROFILE\miniforge3\Scripts\conda.exe create -y -p $env:USERPROFILE\pl-predictor-env `
    python=3.12 numpy pandas scikit-learn xgboost matplotlib jupyter pyarrow joblib

# 3 - verify the exact import that was failing
& $env:USERPROFILE\pl-predictor-env\python.exe -c "import sklearn, scipy; print(sklearn.__version__)"

# register the kernel, then choose "PL Predictor (conda)" in VS Code
& $env:USERPROFILE\pl-predictor-env\python.exe -m ipykernel install --user `
    --name pl-predictor --display-name "PL Predictor (conda)"
Why this is the clean answer

Smart App Control stays on. No registry edits, no Unblock-File (which would not help — this is not a mark-of-the-web block), no reset. You work with the security model instead of switching it off.

If you'd rather not install conda

The whole real pipeline already runs on XGBoost + numpy + pandas, none of which trip the block. model.ipynb is written that way on purpose, with the metrics (confusion, log_loss) hand-rolled in numpy. You only need scikit-learn if you specifically want its RandomForestClassifier — and the teaching notebook shows a hand-built forest and XGBoost's subsample / colsample_bytree are the same two ideas.

Playground

The six toy concepts from the teaching notebook, each rewritten as a small runnable program you can edit in place. Pick a tab, change a number, press Run.

These are written in JavaScript, not Python — a browser page can't run the real scientific Python stack — but the arithmetic is identical line for line, and print(...) works the way you expect. The Python originals, and the library cross-checks, are in teaching-notebook.ipynb.
